# Эксплуатация АВТОWAY

## Ежедневно / по cron

```powershell
# Проверка доступности БД и настройки почты
npm run monitor:check

# Резервная копия SQLite + PRAGMA integrity_check
npm run db:backup

# Проверка последней копии
npm run db:backup:check
```

Рекомендуемое расписание:

- backup — каждый день в 02:00;
- monitor:check — каждые 5 минут;
- проверка восстановления — раз в неделю на копии, не на рабочей БД.

## Безопасность сессий

- Вход: `POST /api/auth/login` — 8 неудачных попыток за 15 минут на пару IP + логин, успешный вход сбрасывает счётчик.
- Токен `admin_token`: HMAC-SHA256, срок жизни 24 часа (`exp` внутри токена), сравнение подписи в постоянное время.
- Выход: `POST /api/auth/logout` — сервер удаляет `httpOnly`-cookie (клиентский JS этого сделать не может).
- **Production:** без `AUTH_SECRET` (не равного `dev-secret`) и `ENCRYPTION_KEY` вход в админку заблокирован. Задайте оба ключа в окружении.
- Если `AUTH_SECRET` менялся, все активные сессии становятся недействительными — это ожидаемо.

## Мониторинг

Админка: `/admin/monitoring`.

Показывает:
- состояние БД и наличие SMTP-настроек;
- ошибки интерфейса, API и серверных маршрутов;
- список резервных копий;
- кнопку создания копии с проверкой целостности.

## E2E-проверки форм

```powershell
npm run test:e2e
```

Проверяются формы контактов, все четыре лендинга, вакансии, продажа, автоподбор и калькулятор аренды. Тестовые заявки автоматически удаляются после прогона.

## Отчёты осмотра

Админка: `/admin/reports` (права `autopodbor.*`).

- Отчёт создаётся вручную: автомобиль, клиент, VIN, пробег, вердикт, заключение, пункты проверки, расходы и фото.
- Пока отчёт не опубликован — ссылка `/report/[token]` отдаёт 404.
- После публикации клиент получает приватную ссылку; страница закрыта от индексации (`noindex`).
- На странице есть кнопка печати/сохранения в PDF.
- Ссылку можно скопировать из списка отчётов.

## Уведомления о заявках (Telegram)

Админка: `/admin/notifications`. Доступ — право `audit.view`.

- Создайте бота у `@BotFather`, получите токен.
- Добавьте бота в рабочий чат/канал, укажите Chat ID (`-100…`) или `@username`.
- Включите уведомления и нажмите «Отправить тест».
- Токен хранится в БД в зашифрованном виде (`ENCRYPTION_KEY`).
- Уведомления приходят по всем источникам: общие формы, лендинги, аренда, продажа, автоподбор.
- Ошибки отправки пишутся в `system_events` и видны в `/admin/monitoring`.

## Нормализация телефонов

После изменения схемы или импорта старых заявок:

```powershell
npm run db:backfill:phones
```

Скрипт идемпотентный: заполняет только пустые `normalized_phone`. По этому полю работают карточка клиента и агрегация в CRM.

## Аналитика и SEO

Админка: `/admin/analytics`.

- Google Analytics 4: Measurement ID вида `G-XXXXXXXXXX`.
- Яндекс.Метрика: номер счётчика + Вебвизор.
- Google Search Console и Яндекс.Вебмастер: verification-коды.
- SEO-заголовок/описание по умолчанию, OG-изображение.
- Аварийный `noindex` для всего сайта.
- Внутренняя сводка заявок по дням, источникам, услугам, UTM и страницам.

Счётчики подключаются только на публичной части сайта. Цели отправляются как `lead_submit` с параметром `lead_source`, клики по телефону/мессенджерам — как `phone_click`, `whatsapp_click`, `telegram_click`, `viber_click`.

Для production после изменения настроек выполняется ревалидация layout; в dev изменения применяются сразу.

## Контент лендингов

Админка: `/admin/landings`.

Хранится в таблице `service_landings`:
- SEO и Open Graph;
- первый экран;
- секции преимуществ/шагов/цен/направлений/аудиторий/сравнения;
- FAQ;
- CTA, тексты формы и sticky-кнопки.

Сид: `npm run db:seed:landings` (также входит в `npm run db:seed`).

## CRM

- `/admin/requests` — единый inbox;
- `/admin/clients` — история клиента по телефону;
- `/admin/tasks` — задачи и напоминания;
- CRM-поля заявки: ответственный, следующий контакт, причина отказа, внутренняя заметка, заметки и задачи.

Все CRM-данные хранятся в `lead_meta`, `lead_notes`, `lead_tasks`.
