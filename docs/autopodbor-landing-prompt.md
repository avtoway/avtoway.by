## 1. Задача

Сделать **продающий лендинг автоподбора** на существующем маршруте `/services/inspection` (slug `inspection` уже есть в таблице `services`) и **полноценную админку** для управления этим лендингом без разработчика.

Лендинг должен:

1. Продавать 4 основных продукта: разовый осмотр, эксперт на день, подбор «под ключ», подбор из-за границы.
2. Снимать страхи покупателя б/у авто: скрученный пробег, скрытые ДТП, залоги, «конструктор», перекупщики, дорогой ремонт.
3. Показывать экспертизу: 100+ параметров, пример отчёта, кейсы с цифрами, гарантии, реальные отзывы.
4. Собирать заявки через квиз и финальную форму, с квалификацией лида (город, бюджет, задача, срок).
5. Быть визуально на уровне главной страницы АВТОWAY: тёмный кинематографичный дизайн, красный акцент, крупная типографика, аккуратные анимации.
6. Быть полностью управляемым из админки: тексты, цены, тарифы, этапы, чек-лист, кейсы, отзывы, FAQ, фото, SEO, заявки.

**Не делай** онлайн-оплату, личный кабинет клиента, автоматическую проверку VIN через API и отдельные городские страницы на этом этапе. Предусмотри заделы, но не реализуй.

## 3. Позиционирование, аудитория, оффер

### 3.1. Позиционирование

**АВТОWAY — независимый автоподбор, который работает только на покупателя.** Мы не автосалон, не перекупщик и не продаём машины. Наша задача — найти живой автомобиль, проверить его до сделки и сторговать больше, чем стоит услуга.

### 3.2. Аудитория

| Сегмент | Бюджет | Что важно |
|---|---|---|
| Первый автомобиль | до $10–15k | Простота, недорогой осмотр, сопровождение |
| Семейный автомобиль | $15–35k | Надёжность, отчёт, гарантия, торг |
| Премиум | $35k+ | Глубокая диагностика, юр. чистота, конфиденциальность |
| Авто из Европы/США/Кореи/Китая | $15–60k | Полный цикл, логистика, растаможка, отчёты |
| Занятой клиент | любой | «Эксперт на день», дистанционно, отчёт в мессенджер |

### 3.3. Главный оффер

> **Найдём живое авто, а не красивую картинку.**
> Проверим кузов, технику, пробег и документы до сделки. Найдём вариант, который не придётся ремонтировать сразу после покупки, — и сторгуем больше, чем стоит наша услуга.

### 3.4. Тон коммуникации

- Прямой, спокойный, без «уникальных предложений» и «команды профессионалов с многолетним опытом».
- Не обещаем «идеальную машину». Обещаем **проверку, отчёт и честный вердикт**.
- Конкретика вместо пафоса: цифры, сроки, что входит, что будет, если авто не подошло.
- «Мы» — про процесс, «я» — в блоке эксперта.
- Не выдумывать статистику, количество подобранных авто, отзывы и гарантии. Все цифры — из админки; если значения нет, блок скрывается.

### 5.2. Типографика

- Не использовать больше 2–3 размеров в одной карточке.

### 5.3. Сетка и ритм

- Контейнер: `mx-auto max-w-6xl px-6` (для широких блоков — `max-w-7xl`).
- Секции: `py-20 sm:py-24 lg:py-32`, разделитель `border-t border-zinc-800/50`.
- Внутренние отступы карточек: `p-5 sm:p-6 lg:p-8`.
- Вертикальный ритм: заголовок → 3–4 строки описания → контент; не ставить всё вплотную.
- Чередовать: тёмный фон → лёгкий градиент/свечение → тёмный фон. Не делать каждую секцию «карточкой в карточке».

### 5.4. Кнопки

- Small: `rounded-lg bg-red-600 px-4 py-2 text-sm font-medium text-white hover:bg-red-700`.
- Все кнопки с `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-red-500 focus-visible:ring-offset-2 focus-visible:ring-offset-zinc-950`.

### 5.5. Карточки

- Базовая: `rounded-2xl border border-zinc-800 bg-zinc-900/40 transition-all duration-300 hover:-translate-y-0.5 hover:border-zinc-700 hover:bg-zinc-900`.
- Тариф «популярный»: `border-primary/40 bg-gradient-to-b from-red-500/10 to-zinc-900/40 shadow-xl shadow-red-500/5`.
- Внутри — без «тяжёлых» теней и лишних рамок.

### 5.6. Анимации

- Использовать существующий `Reveal` (IntersectionObserver) с задержками 0/100/150/200 мс.
- Hover: `-translate-y-0.5`, `scale-[1.02]` для фото, 200–300 мс.
- Счётчики — `AnimatedCounter`.
- Не использовать параллакс, автопрокрутку и тяжёлые видео на мобильных.
- Уважать `prefers-reduced-motion`: отключать `animate-*` и `transition` для таких пользователей.
- Никаких «прыгающих» элементов и мигания.

### 5.7. Фоны и атмосфера

- Допустимы: радиальные красные свечения (`bg-[radial-gradient(...)]`), тонкая сетка, шум, градиенты от чёрного к графиту.
- Не использовать: яркие кислотные градиенты, стоковые «коллажи», эмодзи в публичном UI, тяжёлые parallax-фоны.
- На hero — одно фоновое фото/изображение с тёмным градиентом слева для читаемости текста.

### 5.8. Иконки

- Использовать линейные SVG 24×24, `stroke-width=2`, `currentColor`.
- Добавить в `src/shared/ui/icons.tsx` недостающие: `search`, `shield-check`, `document-check`, `wrench`, `car`, `gauge`, `scale`, `map-pin`, `clock`, `star`, `telegram`, `whatsapp`, `viber`, `phone`, `arrow-right`, `check`, `x`, `chevron-down`.
- Не использовать эмодзи в публичной части (в админке допустимо, но лучше тоже SVG).

## 7. Формы: валидация, безопасность, UX

### 7.1. Zod-схема заявки

Создать `src/entities/autopodbor/autopodbor.schema.ts`:

```ts
import { z } from "zod";

export const autopodborLeadSchema = z.object({
  name: z.string().trim().min(2, "Укажите имя").max(50),
  phone: z.string().trim().min(7, "Укажите телефон").max(20)
    .regex(/^[+\d\s()\-]+$/, "Некорректный телефон"),
  email: z.string().trim().email("Некорректный email").max(100).optional().or(z.literal("")),
  messenger: z.enum(["telegram", "whatsapp", "viber", "call"]).optional(),
  city: z.string().trim().max(60).optional(),
  budgetFrom: z.coerce.number().int().min(0).max(1_000_000).optional(),
  budgetTo: z.coerce.number().int().min(0).max(1_000_000).optional(),
  brand: z.string().trim().max(60).optional(),
  model: z.string().trim().max(60).optional(),
  serviceSlug: z.string().trim().max(60).optional(),
  comment: z.string().trim().max(1000).optional(),
  consent: z.literal(true, { message: "Нужно согласие на обработку данных" }),
  source: z.enum(["quiz", "form", "callback"]).default("form"),
  quiz: z.record(z.string(), z.unknown()).optional(),
  company: z.string().max(0).optional(), // honeypot
  pageUrl: z.string().max(500).optional(),
  utmSource: z.string().max(100).optional(),
  utmMedium: z.string().max(100).optional(),
  utmCampaign: z.string().max(100).optional(),
}).refine(
  (v) => v.phone || v.email,
  { message: "Укажите телефон или email", path: ["phone"] },
).refine(
  (v) => v.budgetFrom == null || v.budgetTo == null || v.budgetFrom <= v.budgetTo,
  { message: "Бюджет «от» не может быть больше «до»", path: ["budgetTo"] },
);
```

Требования:

- Пустые строки бюджетов (`""`) преобразовывать в `undefined` **до** `z.coerce.number()`, иначе они станут `0`.
- Сервер **никогда не доверяет** клиентским суммам/тарифам; берёт цену из БД для отображения, но в заявку пишет только `serviceSlug` и `priceQuoted` (если нужно).
- Санитизация: trim, ограничение длины, удаление управляющих символов.
- Honeypot: если `company` не пустой — вернуть `{ ok: true }` и не создавать лид (антиспам).
- Rate limit: 5 заявок / 10 минут с IP; добавить путь в `src/proxy.ts`.
- Логировать ошибки, но не отдавать внутренние детали.
- Возвращать `{ ok: true, data: { id } }`.

### 7.2. UX формы

- Ошибки — под полем, `aria-describedby`, `aria-invalid`.
- Не блокировать кнопку до заполнения — показывать ошибки после submit.
- Состояния: `idle`, `sending`, `success`, `error`.
- Не сбрасывать данные при ошибке.
- После успеха — фокус на сообщение, `role="status"`.
- Телефон/мессенджер — ссылки `tel:`, `https://t.me/...`.
- Кнопка `Отправить ещё одну заявку` после успеха.

## 8. Админка

### 8.1. Маршрут и меню

- Основной маршрут: **`/admin/inspection`** (в `auth-layout.tsx` уже есть title override).
- Дочерние (опционально, если удобнее):
  - `/admin/inspection` — обзор + табы;
  - `/admin/inspection/requests` — заявки (можно табом).

- Добавить в `TITLE_OVERRIDE`: `/admin/inspection` → `Автоподбор`.
- В `src/proxy.ts` защитить `/admin/inspection` правом `autopodbor.manage` (и `autopodbor.view` для просмотра).

### 8.2. Права

| Право | Что даёт |
|---|---|
| `autopodbor.view` | Просмотр лендинга, тарифов, заявок (read-only) |
| `autopodbor.manage` | Полное управление контентом и настройками |
| `autopodbor.requests` | Просмотр и обработка заявок, смена статуса, заметки |

Seeder:

- Администратор: все три.

- Только `isActive`/`isPublished`, сортировка по `sortOrder`.
- `Cache-Control: public, s-maxage=300, stale-while-revalidate=600`.
- Если `settings.isActive === false` — вернуть `{ ok: true, data: null }` (лендинг отдаёт 404).

`POST /api/autopodbor/leads`

- Публичный, zod-валидация, honeypot, rate limit.
- `serviceSlug` проверять по БД; `serviceTitle` брать из БД, не из клиента.
- `quiz` сохранять как JSON-строку.
- Не сохранять `company` (honeypot).
- Ответ: `{ ok: true, data: { id } }`.
- Ошибки: 400 с человеческим текстом, 429 «Слишком много заявок».

## 14. SEO, аналитика, доступность, производительность

### 14.1. SEO

- Один H1, иерархия H2/H3.
- Хлебные крошки + JSON-LD.
- Внутренние ссылки: `/services/rent`, `/services/sell`, `/contacts`, `/about`.
- `alt` у всех изображений — из БД, осмысленный.
- Тексты не «для поиска», а для людей; ключи — естественно.
- `sitemap.xml` — добавить страницу.
- `robots.txt` — не закрывать.
- Не использовать скрытый текст и клоакинг.

### 14.2. Аналитика

События (в `dataLayer` или `window.dispatchEvent`):

- `autopodbor_view`
- `tariff_view` / `tariff_cta_click` (`tariff_slug`)
- `quiz_start`, `quiz_step` (`step`), `quiz_complete`
- `lead_submit` (`source`, `service_slug`, `city`, `budget`)
- `phone_click`, `telegram_click`, `whatsapp_click`
- `report_view`, `faq_open` (`question`)
- `sticky_cta_click`

Если GTM/Метрики нет — не ломать страницу, просто не отправлять.

### 14.3. Доступность

- Контраст текста ≥ 4.5:1 (кроме декоративных подписей).
- Все интерактивные элементы доступны с клавиатуры, `focus-visible`.
- `aria-expanded` у аккордеонов, `aria-controls`, `role="region"`.
- Формы: `<label>`, `aria-invalid`, `aria-describedby`.
- Изображения: `alt`; декоративные — `alt=""`.
- Не полагаться только на цвет (статусы — текст + цвет).
- `prefers-reduced-motion`.
- Табы — `role="tablist"`, `role="tab"`, `aria-selected`, клавиши стрелок.

### 14.4. Производительность

- Server Components для контента; клиентские — только квиз, табы, аккордеон, галерея, sticky CTA.
- `next/image` с `sizes`, `priority` только для hero.
- Не грузить все фото кейсов сразу — lazy.
- Не подключать тяжёлые библиотеки (swiper, framer-motion) без необходимости.
- Цель: LCP < 2.5s на 4G, CLS < 0.1, INP < 200ms.
- Проверить `npm run build` и размер бандла.
